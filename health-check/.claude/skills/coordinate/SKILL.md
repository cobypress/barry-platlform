---
name: coordinate
description: Start an orchestrator session for the Black Cloud health check (engine and console). Reads the method and the ledger, reconciles them with git, then plans, delegates, reviews and merges the next work until a wave of merges is done or half the context is used.
---

You are the orchestrator. Read `docs/orchestration.md` before anything else: it's the method, and it overrides habit.

The ledger folder is `~/Desktop/Black Cloud/orchestration/health-check` (call it LEDGER below).

## Start

1. **One orchestrator at a time.** If `LEDGER/orchestrator.lock` exists and the process it names is alive (`kill -0 <pid>`), stop at once and say so. Otherwise write the lock: your shell's parent process id, the time, and "coordinate".
2. **Stop if Coby is needed.** If `LEDGER/WAITING-FOR-COBY.md` exists, add anything new to it, remove the lock and stop.
3. **Read** `LEDGER/ledger.md`, the newest `LEDGER/morning-*.md`, the last 20 rows of `docs/lessons.md`, and `CLAUDE.md`.
4. **Reconcile with git; git wins.** For both repos, `git log --oneline -15 <working branch>`, `git worktree list` and `git branch --no-merged <working branch>`. Correct the ledger wherever it disagrees: tips, open branches, worktrees and what each waits on. Branches already merged into the working branch with a clean worktree can be removed (`git worktree remove`, `git branch -d`); note each in the morning report. A lane the ledger says is building, with no agent alive, was cut off: look at its worktree's `git status` and last commit time, treat the last commit as a draft that no gate or mutation has vouched for, and send a finishing builder the round's saved brief (`LEDGER/briefs/`) with that state, to check it item by item, not to carry on from where it looks to have stopped.
5. **Check Coby's side.** `git fetch -q` and compare `origin/health-check` (engine) and `origin/main` (console) with the ledger's "Waiting for Coby" list, and tick off what he has done.

## Work

6. **Pick from "Next"** in the ledger, in order, skipping what's parked. Decide everything except Coby's list in `docs/orchestration.md` ("Waiting for Coby"). Record each product or design decision in `docs/DECISIONS.md` with its reason.
7. **Plan, then brief.** For each lane (at most three at once): the plan with a "done when" checkable without judgement, then a self-contained builder brief. Use a scout for any code fact you'd otherwise state from memory. A decision's premise is a code fact too ("the report has no ceiling", "nothing else reads this"): have a scout confirm it with path:line before the row is written, because a builder builds exactly what the row says. A figure or a reason carried over from the ledger or an earlier report (a pixel count, a line count, "the microsite is team-level") is a premise as well: have it measured or looked up again on the current tip before it goes in a row, and where it can't be, write the row's "done when" so the builder measures first and reports the number. Where a document or file goes (the customer's Drive folder, the console, Claude, or nowhere beyond the worker's run folder) is a premise too: have a scout follow it to its upload or send, with path:line, before a row or brief calls anything internal. When a lane raises an extract step's version or changes its query, the brief asks what a run in flight reads when it resumes (the step runs again, at the run's original date): its window needs an end at that date, and the "done when" has a resume test. When a lane changes what a read takes in without raising its step's version, the brief also asks what a run in flight already holds from before the deploy (a reused checkpoint, a keyset's kept pages) beside the steps it reads after it, and the "done when" tests that mixed state; if the answer is wrong figures, raise the version. A limit a decision row admits ("a deal closed since shows as…") is a planted case in the figure test, with what the customer then reads asserted: a fixture that steers round it proves nothing. When a fix hands one read a list worked out at another read's moment ("the deals closed since", made when the deals were read, used against a read made later), the brief asks which steps run between the two and what a stop and resume there does: the list belongs to the read that happens last, and the "done when" stops a run between the two steps. Two reads set against each other inside one step are both read afresh or both resumable, never one of each: the brief says which, and the "done when" stops the step between them. And when a brief sets a list chosen by one definition against deals chosen by another (Salesforce's `IsClosed` against the calibration's open stages), it names the records on which the two disagree and plants one. When a lane sets one run's kept file beside another run's (a baseline, an earlier pulse, a re-check), the brief asks what code made each: the two can be a year and many parser fixes apart, so a value our code works out is compared only where both files show the same reading, and the "done when" plants an earlier file whose only difference is how we read it. When a decision rests on a test that is meant to force a later action (a pin, a number to raise, a list to keep level), the "done when" replays the past changes that prompted it (undo each named commit in turn) and sees the test fail, and the brief asks where each thing the number vouches for is worked out: when the step reads, or when the file is built. When a decision prints a text that already exists (an assumption, a reason, a label) in a new place, have a scout list every distinct value that text takes on the synthetic org before the row gives a reason for printing it: "the first assumption carries the main input" is a premise about the data. When a fix folds a new case into a state that already exists (an empty number, a flag, a status), the brief lists every sentence and figure printed for that state, and the "done when" asserts each is true of the new case. And when a row has a builder confirm a list "by following the imports", a scout lists the direct imports of each named file first, and the brief marks each one in or out with its reason: the builder is checking a list, not making one. When a lane bounds, filters or otherwise changes what a read takes in, have a scout list every figure that sets that read against another one (a child read reached through its parent, or a second read of the same object), and put each pair in the brief: both reads change together, and the "done when" tests the figure, not only the query's text. What moves the fingerprint is a premise as well: before a brief says a file "must not move", have a scout say what that file quotes (metrics quote their source query, as findings do). When a row or brief says a guard or check "masks" or "stops" a kind of thing (ids, names, links), have a scout say what it does with one it has never seen, and plant that one in the "done when": a guard that knows only the run's own people passes everyone else's. When text is accepted now and printed later (Claude's reply, a consultant's edit), the brief lists everything printing does to it (tokens turned back into names, placeholders shown raw) and the check at acceptance covers each. When a person approves something another actor can still change (a second consultant, the worker), the approval carries what the approver saw (a fingerprint of it) and is refused if that has changed: reading it afresh at the click proves nothing. When a scout's report says what printing or storing does to a text (a writer that replaces characters, a column type that refuses some), each thing it names goes into the row as refused or allowed before the builder starts: a fact the orchestrator holds and leaves out of the row is not built. And when a lane adds a second write to a transaction that already saves something that matters more (a run's results), the brief asks what a value the database refuses does to the first write, and the "done when" plants one: an error path copied from a neighbouring write is a premise about the data. And when a decision relies on a deletion or a sweep as its last line of defence, the brief lists every switch and state in which that code doesn't run (a dry run, a missing client, a failed job) and the "done when" shows the deletion happening in each. When a lane concludes anything from a count or an aggregate ("no records", "none since"), a zero is a premise about what the query can see: have a scout say what the connected user's access is on every route (anyone can connect; Barometer Read Only sees six objects whole), and what Salesforce leaves out of a plain query on that object (archived activities, records hidden by sharing), before the row is written; the row counts only what the run can prove it sees whole, and the "done when" plants a record the user can't see. And when a lane puts a new rule through an engine step that rewrites findings (the guards, the number check), a scout lists every sentence that step prints and the row says which are true of the new rule. When a lane adds text to a page or slide that already has optional parts (lists that can run over, notes that appear only sometimes), the "done when" names the page's fullest case, every optional part present at its longest beside the new text at its longest, and has the builder render it as the documents job does, with and without the new text: a layout test on an ordinary case proves nothing about a full one. And when a row words a new sentence that sets one figure against another or counts something ("X of Y", "in N days", "an average of N"), the row says what is printed at each figure's edges (X above Y, N of 0, a value that rounds to 0) before the builder starts, and a scout says what the number check does with that wording: it refuses "X of Y" when X is the larger, wherever it is printed. When a row changes a shared routine (the carry-over, the number check, a formatter) on the evidence of one page or one finding, have a scout list every other place that routine meets the same shape (every block with a heading, every sentence with a figure) before the row words the rule: a rule read off one slide is a premise about all of them. And when a row has a routine add something beside a thing it finds (a label over a list, a note under a figure), the row says what else can sit where the list sits (a note after it, a closing sentence, a second list) and what is added over each, and says what the addition does to every check that counts the page's or section's content. When a row calls a fault safe ("it can't print", "the check holds it"), that is a claim about every kind of figure and every route: have it run, not read, on a count, a percentage and a money figure before the row says so. And when a lane widens what a rewrite of text by value can match, the brief names what else in the same text can hold that value (another fact of the finding, a quoted constant, the new value itself) and the "done when" plants each. When a row tells a person how to clear a state ("override it back", "approve it again"), the "done when" does exactly that and then goes on to the last check a document passes before it leaves (the printed-page check, the upload), not only to the function the lane changed; and when a row leaves a neighbouring routine alone on purpose, a scout says what that routine is given in every state the lane newly sends people into. And when a row has code look for a figure in free text, a scout counts every digit run in those texts that isn't a figure (a date's parts, an identifier, a time, a token) before the row words what is matched, and the "done when" plants each. When a row borrows another routine's judgement of what a thing is (the number check's reader saying "this is a date"), that judgement is a premise: have a scout quote each rule behind it and say which are guesses from context, and the row treats a guess as unsure, never as certain. And when a row goes on handing input to an old routine after changing what else that routine is given, a scout says what the input still does there, by a run: an input that can now only take away is dropped, not reshaped. And when a row takes an input away from a routine (rows no longer given, a list no longer passed), a scout lists every kind of thing that input acted on (findings and metrics, each field) and what held or changed because of it on the working branch's tip, by a run: the row says what replaces it for each kind, and the "done when" prints one of each kind before and after. Write every lane's decision rows in `docs/DECISIONS.md` yourself and commit them before the builders branch, and tell each builder not to edit that file: rows appended by parallel lanes conflict at merge. When two lanes meet at a contract (one repo writes what the other reads: a column, a file's shape, an error's text), put the contract in both briefs word for word, and have the writing side hold a test of the reading side's limits against everything it can really produce: a reader stricter than its writer fails silently in production. And when a change to one of Coby's files (a security test, a locked file) is written as a patch for him, that it applies proves nothing: apply it uncommitted in the lane's worktree, have a runner run the test it changes by itself from a cold build cache (a test that reads what the dev server has compiled passes or fails by what ran before it), restore the file, and only then list the patch with its counts.
7a. **Save each builder's brief** to `LEDGER/briefs/s<session>-<lane>-<round>.md` before starting the builder, and name the file in the ledger's lane entry: a session can end without warning while the builder works, and the next one needs the brief to finish the round.
8. **Run the loop** from `docs/orchestration.md` for each lane: build, gate (runner), review (adversary, then verifier, then the builder fixes what's CONFIRMED, then gate again), shots for anything a person sees, merge. Start agents in parallel where lanes are independent. Read the whole diff yourself for high-risk changes.
9. **Merge** into the repo's working branch from its main checkout. Update `LEDGER/ledger.md` (tip, lane state) and append the merge to the morning report as each lane merges, not only at the end: a session that dies while waiting leaves the next one to rebuild its state from the session log. After resolving a conflict, run the touched suites and read the summary's `fail` count before `git commit`: never chain the commit after a grep, which succeeds on a failing summary too. Then continue as below (`barry-platlform` on `health-check`; the console's `health-check` lives in `worktrees/hc-console-merge`). Read git's output, run the full gate on the merge through a runner, and fix forward or revert if it fails. The console keeps word-for-word copies of the engine's `src/schemas/*.ts` in `docs/health-check/engine-schemas`, held by its `lib/health-check/__tests__/service.test.ts`: when an engine merge touches `src/schemas`, copy the changed file into the console's `health-check` in the same wave and run that test, and run it once at the end of any session in which the engine moved, even if the console didn't. A console change that Coby should ship goes on a new `hc/release-N` from `origin/main` with `health-check` merged in, full gate run, and its push command listed for him.
10. **Never end with an agent still running** whose report you need. Wait for it.

## Get better

11. When something went wrong, nearly went wrong or was slow, tighten the rule, brief template or agent file that would have prevented it. Never loosen without Coby. Log a row in `docs/lessons.md` and commit that change alone as `playbook: <what>`.

## End

12. End after a wave of merges or at half your context window, whichever is first.
13. Update `LEDGER/ledger.md`: tips, open branches and worktrees, lanes and decision blocks in use, "Waiting for Coby" (each with the exact command or step for him), and "Next".
14. Append to `LEDGER/morning-<today>.md`: what was decided (with decision numbers), merged (hashes) and built, the gate results with counts, playbook changes, and "Still yours".
15. If nothing at all can move without Coby, write `LEDGER/WAITING-FOR-COBY.md`: what's blocked, his exact steps, and what you'll do once he's done.
16. Remove `LEDGER/orchestrator.lock`.
