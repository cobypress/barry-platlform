# Decisions

Newest thinking is in the rationale, not the order. Change a decision by editing it here and saying why.

| # | Decision | Why |
| --- | --- | --- |
| 1 | Node 24 runs TypeScript directly, with no build step | Matches `node --test` in the site, and means one less artefact. Needs a host on Node 24 (see QUESTIONS.md) |
| 2 | Plain `fetch` behind our own client, not jsforce | A library brings write methods we'd then have to prove unreachable. One send path is easy to audit and test |
| 3 | Allowlist by route and operation, not by HTTP method | GETs can run Apex, and POSTs can read. See ARCHITECTURE.md |
| 4 | `listMetadata`, `readMetadata` and `describeMetadata` are refused for now | Nothing uses them. Each read we add is a deliberate change with a test |
| 5 | No Bulk API yet | A bulk query is a POST that creates a job, so it widens the boundary. REST paging covers development orgs. Revisit for large orgs in Milestone 3 |
| 6 | Metadata retrieve over per-flow Tooling reads | One retrieve costs a few calls. Tooling costs one call per flow, because `Metadata` is single-row |
| 7 | Default budget stop at 50% of the org's daily limit, with a 5,000-call cap per run | The customer's integrations keep the larger share. Set by `--budget-share` or `HC_API_BUDGET_SHARE` |
| 8 | Unknown guards block exactly as failed guards do | A guard we couldn't run has told us nothing |
| 9 | Guards are enforced twice: engine and schema | A rule author can't bypass them by mistake |
| 10 | The Default Workflow User is a manual step | We couldn't confirm it's readable by API. Until it's answered, no licence removal is recommended. Confirm on the development org, and automate it if it can be read |
| 11 | Field removal stays "investigate" for now | Report definitions aren't scanned, so that guard stays unknown. Lifting this needs report scanning in Milestone 3 |
| 12 | Dashboard use is not measurable | `LastViewedDate` is per user. The obvious query would call a dashboard the whole team uses "unused" |
| 13 | No decision is separate from lost | Both win rates are reported, because deals that fizzle out would distort a single figure |
| 14 | A deal's close time comes from stage history, using its final closed run | Handles reopened deals, and CloseDate is often edited. CloseDate is the declared fallback |
| 15 | Conversion counts a skipped stage as passed, and reports skips separately | Otherwise a skipped stage shows as impossible conversion above 100% |
| 16 | Medians, not means, for time metrics | One stuck deal shouldn't move the headline |
| 17 | Multi-currency orgs get not measurable on value metrics | Adding amounts in mixed currencies is wrong. Supplying historic rates is future work. Counts still run |
| 18 | Days, months and quarters are UTC | The org's time zone is extracted but not applied yet, so a close late on 31 March Pacific lands in April. The assumption is stated on every metric. Fix in Milestone 3 |
| 19 | Pseudonym tokens are assigned in user id order, per run | Stable within a run. Findings line up across runs by finding id, not token |
| 20 | One-word names aren't scrubbed from free text | "Sales" would turn Sales Cloud into a token. They're still tokenised wherever the engine labels a user |
| 21 | Fixtures are generated by running the real engine against a simulator | Hand-written JSON drifts. The simulator refuses SOQL it doesn't know, and replay refuses unrecorded requests |
| 22 | Ban-list tests aren't used for customer data | A list of customer names would itself put them in the repo. Tests require reserved domains and zero-padded ids instead |
| 23 | The CLI needs `HC_APPROVED_ORG_ALIASES`, empty by default | This machine has customer orgs logged in. One typo must not reach them |
| 24 | The CLI refuses to write inside a git work tree | Rule 8. Run folders hold CRM rows |
| 25 | Black Cloud's design system was readable at the artifact link | Colours and type match the brief. Tokens go in one file in Milestone 4, taken from `colors_and_type.css` in the artifact |
| 26 | Recommended file storage: AWS S3 in `eu-west-2` (London) | See below |
| 27 | The fiscal year comes from the org unless the calibration sets it | A silent January default would give an April-start org the wrong quarters. A mismatch is raised as a finding, and if neither is readable, quarters aren't reported |
| 28 | Deals created already closed count in win rate, but not in conversion, sales cycle or slippage | They're real outcomes with no sales process behind them. Counting won ones as passing every stage while dropping lost ones inflated conversion |
| 29 | The Opportunity extract includes anything modified in the window, or in a calibrated open stage | Otherwise a bulk close of old deals vanishes, inflating win rate and undercounting past pipeline. `IsClosed` alone would let Salesforce decide what's open |
| 30 | A month end is judged on its own history gap (20%) and blank amounts (20%) | One old history row made months before a migration look measured |
| 32 | New reads for security: `SecurityHealthCheck` and `SecurityHealthCheckRisks` (Tooling), `PermissionSet`, `PermissionSetAssignment`, and `ApiType`, `Application` on `LoginHistory`, and sharing defaults on `Organization` | All are SOQL through existing routes, so the allowlist is unchanged. `OauthToken` isn't read, because it holds an authorisation code |
| 33 | New reads for current pipeline: `AccountId` on Opportunity, ids of open deals with `NextStep` filled, `ForecastingType`, `ForecastingQuota` | Text is read as filled or empty by filtering, so it's never fetched |
| 34 | New reads for forecast: `Period`, `ForecastingItem`, `ForecastingFact`. Forecast accuracy is not measurable | These rows are today's position, so they can't show what was called at the time |
| 31 | The instance URL is parsed, and must be a bare https Salesforce host, on connect and refresh | A prefix check passes `https://x.salesforce.com@evil.example`, which sends the token to evil.example |

## File storage

We recommend **AWS S3 in eu-west-2 (London)**, with default KMS encryption, Block Public Access on, and a lifecycle rule that deletes extracts 30 days after delivery.

- **Region:** London keeps data in the UK, which is the simplest story for a UK customer's security review.
- **Fits Vercel:** the browser uploads screenshots straight to S3 through a presigned URL, so the file never passes through a function's request size limit. The worker reads with its own credentials.
- **Deletion:** a lifecycle rule enforces the retention promise even if our own code fails.

Alternatives considered:

- **Vercel Blob:** private stores and region choice exist, but we couldn't confirm a London store, and the region can't be changed afterwards. Reads also go through a function.
- **Cloudflare R2 with EU jurisdiction:** a good fallback if AWS isn't wanted, but it's EU rather than UK.

## New environment variables

Nothing here is needed to run the tests.

| Variable | Needed | Purpose |
| --- | --- | --- |
| `HC_APPROVED_ORG_ALIASES` | For `hc run` | Comma-separated Salesforce CLI aliases this machine may use |
| `HC_API_BUDGET_SHARE` | Optional | Share of the daily limit to stop at. Default 0.5 |
| `HC_SF_API_VERSION` | Optional | Pins an API version. Default is the org's newest |

Expected later: `ANTHROPIC_API_KEY`, `REDIS_URL`, `DATABASE_URL`, object storage credentials, a token encryption key, and the External Client App's client id and secret.
